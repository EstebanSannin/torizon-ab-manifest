Torizon OS — A/B builds

Community builds of the OSTree-free, dual-rootfs A/B variant of Torizon OS, with two updater backends — RAUC and SWUpdate — delivered over Torizon Cloud (aktualizr generic secondary).

↗ Source & manifest ↗ All releases ⚠ dev-signed — not for production

Build it yourself

One command gets a reproducible tree pinned to the tested revisions.

repo init -u https://github.com/EstebanSannin/torizon-ab-manifest -b main \
          -m torizon-ab/tdx/release.xml
repo sync
# then: source setup-environment build; DISTRO=torizon-ab | torizon-ab-rauc; bitbake

Builds

Latest per machine & backend, newest first.

Flashing

x86 / QEMU (.wic): decompress, then write to the target disk.

unxz torizon-minimal-ab-*.wic.xz
sudo bmaptool copy --bmap torizon-minimal-ab-*.wic.bmap torizon-minimal-ab-*.wic /dev/sdX
# or, without bmaptool:  sudo dd if=torizon-minimal-ab-*.wic of=/dev/sdX bs=4M status=progress

Verdin (Toradex boards): a Toradex Easy Installer feed is planned — for now flash the .wic to eMMC via the board's recovery/Tezi flow.

Updating over the air

The A/B rootfs is an aktualizr generic secondary — the same on both backends; only the payload differs.

  1. Provision the device to your Torizon Cloud account.
  2. Upload the payload as a package for hardware id <machine>-rootfs (.raucb for RAUC, .swu for SWUpdate).
  3. Launch an update for the device; aktualizr writes the inactive slot and reboots into it, with the previous slot kept for rollback.

Always verify downloads against each release's SHA256SUMS.

Built automatically from EstebanSannin/torizon-ab-manifest on a self-hosted runner. On-fleet release testing is coming (see the project roadmap).
